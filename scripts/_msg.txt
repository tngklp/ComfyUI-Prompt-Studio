fix(anima): only emit a safety tag when one is chosen, keep character series, order groups correctly

Four prompt-quality bugs, all reproduced from one generated request.

Rating
- The guide's quick-start templates hard-coded `safe`, the checklist demanded exactly
  one safety tag, and the system prompt told the model to open with
  `masterpiece, best quality, score_7, safe`. So selecting None still produced `safe`.
  The templates now carry a `[safety tag]` slot that is dropped when no rating is
  selected, the checklist is conditional, and the system prompt emits a safety tag only
  when one was requested.

Character series
- The guide showed `[character] [series]` as two adjacent groups, which read as "name
  the character, then the series later" and let the series drift or vanish. It is now
  specified as one inseparable pair, `[character, series]`, in the guide, the system
  prompt and the closing contract.
- The audit now reports a character whose series tag is missing, and forces a repair.

Tag order
- Character and series are documented as the same group, sitting after the count tag and
  before the artist, so the ordering rule cannot be satisfied with the series elsewhere.

Detail
- The system prompt said "never pad the prompt"; it now asks for the general-tag group to
  cover appearance, clothing, pose, expression, props, framing, background and lighting
  thoroughly, which is where Anima expects the detail.

Audit now repairs, not just warns
- A rating or style that contradicts the user's own selection forces a repair. These are
  the failures the user cannot see for themselves, and leaving them as warnings shipped
  a prompt that visibly disagreed with the settings.

Extension 1.1.1, standalone 1.2.1.
