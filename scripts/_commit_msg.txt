refactor(anima): fetch the character catalogue automatically and restyle the picker

Removes the "Anima Characters" Settings section entirely. The dataset was already
downloaded automatically, so the section only reported state and offered a retry for
a step the user cannot influence. What is left is a purely automatic fetch:

- the extension starts it on import, on the background thread that was already there;
- the standalone launcher runs it before the app starts, via the new
  standalone/scripts/fetch_characters.py. That was the point of the change: the
  download is now visible and one-off rather than happening behind a window that
  looks like it lost its characters. The app's own startup hook stays as the
  fallback for launching the module directly or from start-linux.sh, and is a no-op
  once the cache is current;

The fetch script is idempotent (silent and immediate when the cache is current) and
resolves the core checkout in both layouts - beside the app in a source tree, under
upstream/ in a ZIP. A failure exits non-zero so the launcher can warn, but the studio
still starts. The manual refresh route, client call and handler are gone, so nothing
in the interface can trigger a 9 MB download.

Picker restyle:
- selected characters render as bubbles in the brand lilac accent, inline rather than
  one per line. The trigger moved into the bubble's title, because it is long enough
  ("hatsune miku, vocaloid") that showing it would wrap every bubble to two or three
  lines and stop them reading as chips;
- the picker is now a plain .ps-field, so its label, control height, border and
  radius come from the same rules as the aspect ratio, content rating and prompt
  style selectors it sits beside, rather than a bespoke panel;
- moved below content rating and prompt style, since those are the guide's own
  options and read first.

Drops the dataset status and warning text from the picker, and the source label from
the character line. index_status() keeps those fields: they are now diagnostics only,
and remain the way to tell from the API whether a deployment is on the real catalogue
or the offline sample.

Verified: Python 643, frontend 397, smoke 2, standalone 34, standalone frontend 4.
