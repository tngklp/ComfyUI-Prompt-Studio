perf(anima): precompute search keys and warm the index at startup

Character search took ~213 ms per keystroke against the full 36k-character AnimaDex
catalogue, which is slow enough to feel laggy behind a 180 ms debounce. Profiling split
that into ~92 ms of `normalize_name` and a per-entry regex match, both recomputed on
every query even though the catalogue does not change.

Search
- Normalised name, series and tags are computed once when the index is built and stored
  in a list parallel to the entries, so a search is only substring tests. 213 -> 29 ms.
- `\b<query>` is compiled once per search instead of rebuilt inside the loop over 36k
  rows.
- `lookup()` gained prebuilt tail-word and collapsed-key buckets. The punctuation step
  was stripping punctuation off all 73k keys on every call (~82 ms); it is now a dict
  hit, and every lookup is sub-millisecond, including `artoria pendragon fate` ->
  `artoria_pendragon_(fate)`.

Startup
- The index is warmed on the existing background thread, so the one-time build happens
  while the studio is opening rather than inside the first search. Measured: the first
  search goes from 888 ms to 32 ms. The call returns in under a millisecond, so a slow
  or unreachable mirror still cannot delay startup.
- `start_background_fetch` now always starts that thread - it skips only the *download*
  when the cache is current. Basing the early-out on the cache alone is what left the
  build on the request path.

Behaviour is unchanged: count-first ordering, `None` on an ambiguous short name, and
verbatim triggers are all re-verified against the live catalogue.
